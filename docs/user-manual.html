Figure 4.1 — Inventory page with summary cards (Available Units, Delivered, Catalogue Items) and tabs for Stock Balances and the Input Catalogue.

Monitor Live GPS Tracking

👤 Admin / Project Manager 🔗 /gps-tracking

GPS Tracking displays real-time vehicle positions on an interactive map with automatic 30-second refresh. Each pin shows the manifest, driver, and last known speed.

Figure 7.1 — Live Vehicle Tracking. The left panel lists active vehicles; the map displays their GPS positions with colour-coded status indicators and a map legend at the bottom.
Steps
  1. Navigate to GPS Tracking in the sidebar
  2. Any vehicle with status In Transit appears as a pin on the map
  3. Click a vehicle card or map pin — a tooltip shows manifest code, driver, distance to destination, and last ping time
  4. The page auto-refreshes every 30 seconds — the Last Ping timestamp updates when a GPS signal is received
  5. Click Tracker Setup to configure GPS tracker credentials for a new vehicle
💡 Pin colour legend: ● Live (<5 min)  |  ● Recent (5–30 min)  |  ● Stale (30–120 min)  |  ● Offline (>2 hrs)

Review Proof of Delivery Records

👤 Admin / Project Manager 🔗 /pod

Every delivery confirmed via the field app creates a PoD record on the server. Supervisors use this module to verify delivery evidence — GPS location, OTP confirmation, and biometric face match — and manage exceptions.

Figure 8.1 — Proof of Delivery: 0 Verified, 2 Pending, 0 Exceptions. The Review Queue tab surfaces records with bypassed OTP or failed face verification.
Steps
  1. Navigate to Proof of Delivery in the sidebar
  2. Review summary cards: Verified, Pending, Exceptions
  3. Click Review Queue tab for records needing supervisor attention (OTP bypass or face fail)
  4. Filter by status — All / Pending / Verified / Exception
  5. Click any PoD row to view detail — GPS map pin, face photo, OTP status, and timestamp
💡 Face Check states: Verified (≥80% match)  |  Failed (<80%, flagged)  |  Bypassed (officer override)  |  NoReference (first delivery, photo saved as future reference)

Stock Reconciliation

👤 Warehouse Manager / Admin 🔗 /reconciliation

After a vehicle returns, the warehouse manager reconciles loaded vs. delivered vs. returned quantities. Approved reconciliations adjust the warehouse balance and flag unexplained variance for investigation.

Figure 9.1 — Reconciliation showing REC-306D22: 100 loaded, 85 delivered, 10 returned, variance +5 — status Approved.
Steps
  1. Navigate to Reconciliation → click New Reconciliation
  2. Select Warehouse Test Warehouse and the manifest from Scenario 6
  3. Enter Delivered and Returned quantities as reported by the driver
  4. Click Submit Reconciliation
Expected
Reconciliation record created. Warehouse stock is adjusted by the returned quantity. Any positive variance is logged and flagged.

Audit Log Review

👤 Admin only 🔗 /audit

The Audit Log records every system event with full user attribution and timestamps. It is append-only, providing a tamper-evident trail for compliance and investigation. An anomaly detection layer automatically flags suspicious patterns.

Figure 13.1 — Audit Logs: 24 events in 30 days. Events-by-action bar chart, 14-day activity trend line, and anomaly detection panel flagging 2 items (9 off-hours events, 1 config change).
Steps
  1. Navigate to Audit Logs in the sidebar
  2. Review the summary stats: Total Events (30D), Active Users, Top Action, Top Module
  3. Check the Anomalies Detected section for any flagged activity requiring review
  4. Use action-type and date-range filters to narrow entries
  5. Verify that all actions from Scenarios 1–12 appear with correct timestamps and user attribution
🔒 Compliance note: Audit records cannot be edited or deleted. The off-hours anomaly detector flags activity between 22:00–06:00 for administrator review.

Submit a Proof of Delivery — 3-Step Flow

📱 Field Officer 🔗 Farmer Profile → Confirm Delivery

This is the core field workflow. From the farmer profile, the officer confirms a delivery through three sequential verification steps, building a tamper-resistant record of who received what, where, and when.

Step 1 — Delivery Details

  1. From the farmer profile, tap Confirm Delivery
  2. The form pre-fills farmer name, campaign, and manifest
  3. Enter: Quantity Delivered 50, Notes Delivered at community centre
  4. Tap Capture GPS → allow location permission
Expected
GPS coordinates captured and displayed. Tap Next.

Step 2 — OTP Verification

  1. Tap Send OTP — a 6-digit code is sent to the farmer's phone via SMS (EasySendSMS)
  2. Button changes to "Resend" with a 60-second cooldown
  3. Ask the farmer for their SMS code → enter it in the 6-digit field → tap Verify
Expected
Green checkmark — "OTP Verified". Tap Next.
📵 No SMS coverage: Tap Skip OTP (amber) → confirm the alert. The step advances with an amber "OTP Skipped" badge — flagged for supervisor review in the web portal PoD queue.

Step 3 — Face Verification

  1. Tap Take Photo → take a clear photo of the farmer's face → tap Use Photo
  2. The app uploads the photo and compares it against the registered reference via AWS Rekognition
Similarity ScoreBadge ShownNext Action
≥ 80%✅ Face VerifiedTap Submit Delivery
< 80%❌ Match FailedTap Override + enter reason
No reference on file⚠️ No ReferencePhoto saved; submit normally
  1. Tap Submit Delivery
Expected
Success screen — "Delivery Confirmed". PoD record is created and immediately visible in the web portal at /pod.

Offline Queue & Sync

📱 Field Officer 🔗 Sync tab — Tab 5

The app fully supports offline operation. Deliveries queued offline are uploaded in bulk when connectivity is restored, ensuring no data loss in remote areas.

Steps
  1. Enable Airplane Mode on the device
  2. Complete Scenarios 16 & 17 with a different farmer
  3. On the final Submit step, tap Save Offline
Expected
Delivery saved to offline queue. A numeric badge appears on the Sync tab.
  1. Disable Airplane Mode to restore connectivity
  2. Tap the Sync tab → review the pending queue
  3. Tap Sync Now
Expected
Progress bar completes → "1 record synced successfully". PoD now appears at /pod on the web portal.
💡 Offline records survive app restarts — they persist in device storage until explicitly synced.
